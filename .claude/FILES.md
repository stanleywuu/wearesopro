# File Map

One-line purpose for every file/directory in the repo. Update this when you add, remove, or repurpose a file.

## Root pages
- `index.html` — Landing page (book cover image, intro).
- `notes.html` — Editor's notes hub: Acknowledgements, Pipeline, Random Thoughts. **Not in the menus** (build notes don't sell the book); reached from the footer site map. `notes/faqs.html` is in The Team menu instead.
- `games.html` — Games & Quizzes hub, links out to each game in `games/`.
- `experiments.html` — "Under construction" page with an email-capture form (posts JSON to a Google Apps Script endpoint, then redirects to `thanks.html`).
- `links.html` — Amazon / Lulu (self-publish) purchase links.
- `feedback.html` — Reader feedback page; links out to a Google Form.
- `team.html` — **The Team** hub: a picture button per character (drawn live from `team/assets/js/team.data.js`), with the name and that profile's own one-line description. The description is repeated here on purpose (crawlers do not run the includes); `make check` fails if a tile's line stops matching its profile.
- `thanks.html` — Success page a form sends you to once it has posted.
- `404.html` — Custom 404 page.
- `robots.txt` — Crawler rules.
- `llms.txt` — LLM/GEO discovery file describing the site for AI crawlers.
- `staticwebapp.config.json` — Route redirect config (e.g. `/intermission` → `/games.html`); leftover-style config, not Netlify's own `_redirects`/`_headers`.
- `README.md` — Human-facing project overview and structure summary.
- `Makefile` — `make site` regenerates the crawlable nav + `sitemap.xml`; `make check` reports missing navs, pages with no CSP meta, and broken internal links; `make hooks` installs the pre-commit hook (once per clone).
- `sitemap.xml` — Generated by `make site`; do not hand-edit.
- `Prompt` — Original project brief/requirements from the user (no extension); source of the core rules in `RULES.md`.

## notes/
- `notes/faqs.html` — FAQ page.
- `notes/pipeline.html` — Explains the book-building pipeline.
- `notes/spreadsheet.html` — Notes tied to a tracking spreadsheet.

## team/
Character profiles. See `docs/team.md`.
- `team/updates.html` — Recent Updates posts (was `teamupdates.html`; the old URL redirects here).
- `team/stanley.html`, `team/tommy.html`, `team/stephanie.html`, `team/dale.html`, `team/ricky.html` — one profile each: the hockey card (`card.js` + `card.css`) beside a bio, quick facts and a buy-the-book button. Adding someone: copy a profile, add their code to `team.data.js`, a `PAGES` entry with `section: "team"`, and a tile on `team.html`.
- `team/assets/js/team.data.js` — `TEAM_CODES`: **the** one place each character's Create A Player code lives. Change how someone looks here and nowhere else.
- `team/assets/js/team.js` — draws the hub's picture buttons (`canvas[data-who]`) and hands a profile's code to its card (`#card[data-who]` → `data-player`).
- `team/assets/css/team.css` — hub roster grid and the profile's card-beside-bio layout.

## partials/ (included via `data-include`, see `assets/js/main.js`)
- `partials/nav.html` — Main site navigation. The dropdown and drawer link lists are **generated** from `PAGES` between `nav:games` / `nav:team` markers — edit `tools/build.py`, not the lists.
- `partials/player-editor.html` — **The** player builder markup (stage, canvas, tabs, all controls), shared by `games/create-a-player.html` and the slot modal on `games/team-photo.html`. Driven by `CAP_EDITOR.mount()`; elements addressed by `data-el`, never by id. Four tabs: Shape, Kit, Face (hair and facial hair), Info. `[data-el="host-actions"]` / `[data-el="host-links"]` / `[data-el="host-footer"]` are empty slots each host page fills with its own buttons - the main action row, the quiet "which player" links, and whatever comes after. See `.claude/RULES.md`, "One builder, two mounts".
- `partials/nav-noscript.html` — **Unused.** Was included inside `<noscript>` via `data-include`, which cannot work (the include needs JS); replaced by the generated `.site-links` nav.
- `partials/sidebar.html` — Sidebar (poll widgets, etc.).
- `partials/footer.html` — Site footer.
- `partials/PLAN.md` — Task tracker for partials-related work (see CLAUDE.md plan conventions).

## games/
- `games.html` — see Root pages above.
- `games/readme.txt` — Placeholder note ("Add your pages here").
- `games/chirp.html` + `games/assets/js/chirp.js` + `games/assets/css/chirp.css` — **Chirp**: guess if Stanley said a quote at work or on the ice.
- `games/whowas.html` + `games/assets/js/whowas.js` + `games/assets/css/whowas.css` — **Who Was**: identify which character matches a clue, 5-question rounds.
- `games/quotes.html` + `games/assets/js/quotes.js` + `games/assets/js/quotes.data.js` + `games/assets/css/quotes.css` — **Quotes Match**: match quotes to characters, streak counter, supports an "Everyone" answer. Data (quotes/choices) kept separate in `quotes.data.js`.
- `games/fighter.html` + `games/assets/js/fighter.js` + `games/assets/css/fighter.css` — **Goalie Brawl**: 2D beat-em-up, Tommy defends the crease against waves of enemies with lane movement and multiple attacks. See `docs/goalie-brawl.md` for design/task history.
- `games/adopt.html` + `games/assets/js/adopt.js` + `games/assets/css/adopt.css` — **Adopt/Train Tommy**: canvas-drawn goalie sprite with poses and training mechanics. See `docs/drawing-code-cleanup.md` for drawing-code history.
- `games/create-a-player.html` + `games/assets/css/create-a-player.css` — **Create A Player**: build a cartoon player (body/head shape, colours, helmet, hair, facial hair, handedness, name, number, catch-phrase) and drag to spin them in 3D. See `docs/create-a-player.md` for the task tracker.
  - `games/assets/js/create-a-player.data.js` — data only: shapes, slider ranges, colour palettes, positions, random name and catch-phrase pools. Enum lists (shapes, helmets, handedness, positions, hair styles, facial hair) are **append-only**: a share code carries the index. `sliders` is append-only too - `height` and the four face sliders (`eyeSize`, `eyeContour`, `mouthLength`, `mouthContour`) were added after v1 and ride at the tail of the code. A slider that has RAISED its minimum keeps the original one in `codeMin`, which is what the code counts from (see `.claude/RULES.md`). `cardEdgeColors` / `cardBackColors` are the card's own border and window, appended at the tail of the code. `pantsColors` / `gloveColors` / `stickColors` are the kit parts that used to be derived - pants and gloves default to **empty**, meaning "follow the jersey", which is how every player built before them still draws.
  - `games/assets/js/migrate.js` — `CAP_MIGRATE`: `upgrade(raw, version, steps)` walks stored data up a ladder of one-step-per-version functions, and flags data written by a newer version of the site (`ahead()`) so it is never rewritten. Used by the player store, the team store and the backup file. See "Stored data carries a version" in `.claude/RULES.md`.
  - `games/assets/js/team-store.js` — `CAP_TEAM`: the roster itself — `localStorage["cap-team"]`, its validation, and its shape (size, which slot is the goalie, where a new player lands). Shared by the Team Photo page and the "Add to team" button on Create A Player, so there is one definition of a roster. No DOM, no drawing.
  - `games/assets/js/player-store.js` — `CAP_PLAYERS`: every player built on this device, `localStorage["cap-players"]`, newest first and capped at 24. Saved automatically as you work, keyed by a session id the builder mints per player so editing updates one entry instead of adding a row per keystroke. A player who has only been **rolled** (Randomize) waits: no entry until something about him is changed, or he is added to the team. Feeds the picker in the team-photo slot modal.
  - `games/assets/js/backup.js` — `CAP_BACKUP`: everything on this device in one JSON file. Export writes the saved players *and* the current team; import validates every code through the codec, merges players (deduped by code, nothing overwritten) and hands the team back to the caller, since restoring a team means replacing the one that is there. Offered in the saved-players panel on Create A Player and under "More" on Team Photo.
  - `games/assets/js/player-gallery.js` — `CAP_GALLERY`: the saved-players panel, shared by both pages that need it. Team Photo opens it to pick somebody for a slot; Create A Player opens it with `canDelete` to manage the collection. Deleting is offered there and nowhere else — on a page with a team in front of you, "remove" reads as "off the team". With `canBackup` the panel also carries the Export/Import row (`CAP_BACKUP`). Past a handful of players it also carries a search box that filters the tiles by name (or position, which is what an unnamed tile is labelled with) as you type.
  - `games/assets/js/share.js` — `CAP_SHARE.link({url, title, host, say})`: hand someone a link, best way first — the system share sheet, then the clipboard, then a selectable box that always works. Shared by the builder's "Share card" and the hockey card's own button.
  - `games/assets/js/pdf.js` — `CAP_PDF`: a very small PDF writer (text, lines, boxes, one JPEG from a canvas) built by hand, because the site has no build step and a PDF is a plain container with an offset table at the end. Points, origin bottom-left.
  - `games/assets/js/card-surface.js` — `CAP_SURFACE.canvas(ctx, w, h, scale)`: a canvas that takes the same instructions as `CAP_PDF.doc()` (points, origin bottom-left, grey 0-1). The printable card is laid out once and drawn twice - PDF to print, PNG to edit - so the two cannot drift apart.
  - `games/assets/js/card-print.js` — `CAP_PRINT`: the printable card - front and back side by side at 2.5x3.5in on US Letter, dashed cut lines. The stat boxes and bio lines are **empty on purpose** (print it and fill it in), and the site's name appears nowhere on the card: nobody prints someone else's watermark. Default sheet is the SAME card twice (one to keep, one to give); `allPoses` prints one of each picture. `MOMENTS` holds three frames per **reel** - a defenceman's windup hides the stick behind his body, so his are the glide and the follow-through - and `poses(params, reel)` cuts the stills from the player's own highlight unless the card page's picker names another. That picker changes the printed sheet only: the reel is rolled off the share code and nobody chooses what someone else sees. `savePng()` hands out the same card - front and back, already formatted - as a PNG for anyone who wants to edit it.
  - `games/assets/js/seed.js` — `CAP_SEED.stream(text)`: hash a player's code and pull a stream of numbers off it. **The** one copy - the card's season and the choice of highlight both need it, and two copies drift. Load it before `card-stats.js` / `create-a-player.reel.js`.
  - `games/assets/js/card-stats.js` — `CAP_STATS`: the stat line on the on-screen back, drawn from the player's own code through `CAP_SEED` so the same player always shows the same season, with nothing stored. Goalies get GP/W/L/SV%.
  - `games/assets/js/create-a-player.codec.js` — `CAP_CODE`: the player parameter defaults, the share code (encode/decode) and `sanitize()`, the one whitelist every untrusted player passes through. **v2** is what it writes: every number as fixed-width base64 digits with no separators, then the free text as `~` fields (a `~` or `%` in a name is escaped - v1 could not hold one). Zero means the default throughout, so a run of defaults at the end trims off and a field added later reads as its default out of an older code. **v1 is frozen and still read**, along with the pre-compact base64 JSON before it, so every link ever shared keeps working. No DOM, no drawing; shared by the builder and the team photo page.
  - `games/assets/js/create-a-player.draw.js` — hand-rolled 2.5D renderer (no 3D library): silhouette slabs whose width, position, depth and shading are recomputed from the yaw angle. `position: "Goalie"` switches in pads, blocker, trapper, a paddle stick and the upright hands-on-the-knob rest pose. No DOM access. `render(ctx, params, yaw, anim, opts)` obeys the current canvas transform, and `opts.background:false` drops the ice fill so several players can be composited into one scene.
  - `games/assets/js/create-a-player.reel.js` — `CAP_REEL`: **the** Highlight timeline. `build(params, code, kind)` picks the highlight, `at(reel, ms)` returns the pose/puck/camera for that moment (null once finished). Which highlight is **rolled off the player's own code** (same hash-and-stream idea as `CAP_STATS`), never `Math.random`: a shared card plays what the builder showed, and a replay plays the same one. Three for a skater - the shot (wrist, or a slapshot from the point), the wipeout (loses an edge, `anim.fall`, and `anim.boards` puts the dasher behind him since there is no net in it) and the spin-o-rama (`anim.yaw` turns the camera mid-run) - and two for a goalie: three saves in a row, or a scramble - five with no gaps while he pushes across the crease. `?debug=reel&kind=<name>` forces one; `KINDS` lists them. No DOM, no drawing. Played by the builder and by every hockey card (card page and `team/` profiles), so there is one highlight, not copies. Load it after `create-a-player.draw.js`.
  - `games/assets/js/create-a-player.editor.js` — `CAP_EDITOR.mount(root, params, opts)`: the builder as a mountable widget — tabs, option pickers, swatches, sliders, identity fields, drag/auto-spin, randomize, the Highlight button (timeline in `CAP_REEL`), `?debug` yaw grid and `?debug=reel` filmstrip (the highlight laid out as frames, since a four-second animation cannot be judged one run at a time). Scoped strictly to its `root`, so it also runs inside the team-photo slot modal. `destroy()` stops its render loop, `addLink(label, run)` builds the quiet link row under the status line (both mounts have one), and `startNaming()` opens the Info tab with the cursor in Name.
  - `games/assets/js/create-a-player.js` — the *page* only: mounts the editor on `partials:ready`, quiet autosave to localStorage, `?p=` share links (whitelisted on load), the collapsed view a shared link opens in, the "Add to team" button, and "Paste a code" (desktop width only: load a player code or `?p=` link as a new saved player). Share hands over the **hockey card** URL, not the builder's.

- `games/team-photo.html` + `games/assets/js/team-photo.js` + `games/assets/css/team-photo.css` — **Team Photo**: a line-up of slots; tapping one opens the Create A Player builder in a modal (a `CAP_EDITOR` mount on `partials/player-editor.html`) and saves that player into the slot. Two rows on risers composited into one canvas with `CAP_DRAW.render(..., {background:false})`. A slot holds a *copy*: saving writes the team and nothing else, and "Save as" is the only path from here into your saved players. Team kept in `localStorage["cap-team"]`; `?t=` carries a whole team as a length-framed code (free text means no separator is safe to split on) and never overwrites the stored team without a press. `?debug` fills every empty spot with a random player, in memory only. See `docs/team-photo.md`.
- `games/card.html` + `games/assets/js/card.js` + `games/assets/css/card.css` — **Hockey Card**: one player from a `?p=` code, with its own Share button (`CAP_SHARE`), laid out like a card off the shelf, except the picture is their Highlight on a loop. Reached from the highlighted "View hockey card" button on a shared player. Also the picture on every `team/` profile: with no `?p=`, `card.js` reads the code from `#card`'s `data-player`. Deliberately absent from the nav and footer (`PAGES` entry has no label or section): with no player in the URL it is an empty page. It plays the builder's own Highlight (`CAP_REEL`) on a loop, holding on the last frame between runs. The print panel (`?debug=print` opens it) picks which of the three pictures to print and, above them, which highlight to cut them from.

## tools/
- `tools/build.py` — Generates the footer site map in every page, the nav/drawer menus in `partials/nav.html`, and `sitemap.xml` — all from one `PAGES` list. Run via `make site`. Standard library only; not part of the deploy.
- `tools/templates/site-links.html` — Markup template for the generated nav block; `{{links}}` is where the links go. First and last lines are the markers `build.py` searches for.
- `tools/templates/site-link.html` — Markup template for one nav link (`{{href}}`, `{{label}}`).
- `tools/templates/nav-item.html` — Markup template for one dropdown/drawer `<li>`; used for both the desktop menu and the mobile drawer.
- `tools/ogcards/card.html` + `card.css` + `card.js` + `shoot.sh` — Share-card generator (1200x630). Reads the look from `TEAM_CODES` and the words from the page the card is for, so nothing is duplicated; `shoot.sh` screenshots each card and writes `assets/img/og-<slug>.jpg`. Dev only - it is served like any other file, but nothing links to it. Recipe: `docs/page-metadata.md`.
- `tools/shot.sh` — Screenshot a local page with headless Chrome: `sh tools/shot.sh /team.html out.png [w] [h]`. Carries the flags that matter - `--password-store=basic --use-mock-keychain` (otherwise Chrome asks the desktop to unlock its keyring and a dialog pops up on whoever's screen), a throwaway profile, and `--disable-dev-shm-usage`. Dev only.
- `tools/hooks/pre-commit` — Runs `make site` and the link check before every commit; blocks the commit if generated output is stale or a link is broken. Install with `make hooks`.
